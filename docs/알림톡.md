# 알림톡 준비하기

풀이를 다 쓰면 카카오톡으로 알리고 PDF 를 보내 주는 기능이다. **코드는 다 되어 있고,
아래 등록 절차가 끝나야 실제로 나간다.** 그 전까지는 보낼 문구를 서버 로그에 찍기만 한다
(`[notify] (모의) …`). 설정이 없다고 결제나 풀이 생성이 멈추지는 않는다.

## 왜 알림톡인가

카카오톡 메시지에는 두 갈래가 있다.

| | 알림톡 | 나에게 보내기 |
|---|---|---|
| 받는 사람 | 전화번호만 알면 누구나 | 카카오로 로그인한 본인만 |
| 사전 준비 | 채널·발신프로필·템플릿 심사 | 없음 |
| 비용 | 건당 과금 (9원 안팎) | 무료 |
| 문구 | 심사받은 템플릿만 | 자유 |

알림톡을 골랐으므로 준비가 필요하다. 심사에 보통 영업일 1~3일 걸린다.

## 1. 카카오 비즈니스 채널

1. [카카오 비즈니스](https://business.kakao.com) 에서 채널을 만든다.
2. 사업자 정보로 **비즈니스 인증**을 받는다.
   - 상호: 르노바 / 등록번호: 656-26-02081 / 대표: 이재호
3. 채널 검색용 아이디를 정한다 (예: `@운명대로`).

## 2. 발송 대행사 (솔라피)

알림톡은 카카오와 직접 연결하지 않고 대행사를 거친다. 이 저장소는 솔라피를 쓴다
(`lib/notify/solapi.ts`). 다른 곳을 쓰려면 `NotifySender` 만 새로 구현하면 된다.

1. [솔라피](https://solapi.com) 가입 → **API Key / API Secret** 발급
2. **발신번호 등록** — 통신서비스 이용증명원이 필요하다. 알림톡이 막혔을 때
   문자로 대신 보내는 데 쓰인다.
3. **카카오 비즈니스 채널 연동** → `pfId` 를 받는다.

## 3. 템플릿 등록

문구는 `lib/notify/templates.ts` 의 `body` 에 있다. **그 파일의 글자를 그대로** 솔라피
템플릿 등록 화면에 붙여 넣고 심사를 넣는다. 통과하면 나오는 템플릿 ID 를 환경변수에 적는다.

### 템플릿 ① 운명대로_풀이시작

```
[운명대로] 풀이를 시작했어요

#{이름}님의 「#{상품}」 풀이를 쓰기 시작했습니다.
완성되면 다시 알려드릴게요.

주문번호: #{주문번호}
```

- 버튼: 웹링크 `진행 상황 보기` → `https://www.unmyeongdaero.com/v/#{코드}` (모바일·PC 동일)
- 분류: 서비스 이용 > 처리 진행

### 템플릿 ② 운명대로_풀이완성

```
[운명대로] 풀이가 완성됐어요

#{이름}님의 「#{상품}」 풀이가 준비됐습니다.
아래 버튼으로 전문을 읽거나 PDF로 받아 보실 수 있어요.

발행일: #{발행일}
주문번호: #{주문번호}

보관함에서 언제든 다시 보실 수 있습니다.
```

- 버튼 1: 웹링크 `보고서 열기` → `https://www.unmyeongdaero.com/v/#{코드}` (모바일·PC 동일)
- 버튼 2: 웹링크 `PDF 받기` → `https://www.unmyeongdaero.com/r/#{코드}` (모바일·PC 동일)
- 분류: 서비스 이용 > 처리 완료

### 심사에서 걸리는 것들

- **광고 문구를 넣지 말 것.** 할인·이벤트·추천이 들어가면 광고성으로 분류되어 수신동의와
  `(광고)` 표기가 필요해진다. 테스트로 막아 두었다(`lib/notify/__tests__`).
- **링크 도메인을 등록할 것.** `unmyeongdaero.com` 을 채널에 등록해 두어야 버튼이 통과한다.
  PDF 링크를 스토리지 주소(`…supabase.co`)가 아니라 `/r/{코드}` 로 우리 도메인에서
  받는 이유가 이것이다.
- **버튼 링크는 코드 한 조각만 변수로 둔다.** 상품마다 주소가 달라지면 템플릿을 상품 수만큼
  만들어야 하므로, `/v/{코드}`·`/r/{코드}` 로 고정하고 어디로 보낼지는 서버가 정한다.
- 치환 변수는 `#{이름}` 처럼 쓰고, 변수만으로 이루어진 줄은 만들지 않는다.

## 4. 환경변수

```
SOLAPI_API_KEY=
SOLAPI_API_SECRET=
SOLAPI_SENDER=01012345678        # 등록한 발신번호, 하이픈 없이
KAKAO_PF_ID=
KAKAO_TEMPLATE_STARTED=          # 템플릿 ① ID
KAKAO_TEMPLATE_READY=            # 템플릿 ② ID
```

여섯 개가 모두 있어야 실제 발송으로 바뀐다. 하나라도 비면 모의 발송(로그)으로 남는다.
Vercel 에 넣을 때 **Sensitive 가 아닌 일반 값**으로 넣는다 — Sensitive 는 런타임에서 읽히지 않는다.

## 5. 데이터베이스

`supabase/migrations/0002_notify_and_pdf.sql` 을 Supabase SQL 편집기에서 실행한다.
전화번호 칸과 PDF 보관 칸, 그리고 비공개 `reports` 버킷을 만든다.

## 동작 순서

1. 풀이 신청 화면에서 번호를 적는다(선택). 적지 않으면 알림은 가지 않는다.
2. 생성이 시작되면 **템플릿 ①** 이 나간다.
3. 다 쓰이면 PDF 를 구워 스토리지에 올리고 **템플릿 ②** 가 나간다.
4. 버튼을 누르면 `/v/{코드}`(보고서) 또는 `/r/{코드}`(PDF)로 들어와,
   **로그인한 본인인지 확인한 뒤** 보고서 화면이나 10분짜리 서명 주소로 넘어간다.
   링크가 남에게 전달돼도 남의 풀이는 열리지 않는다.

같은 단계의 알림은 두 번 가지 않는다(`readings.notified_kind`). 생성이 실패해 다시 돌아도
"시작했어요"가 또 가지 않는다.

## 개인정보

- 번호는 이 알림에만 쓴다. 광고는 보내지 않는다.
- 받아 둔 시각을 `notify_consent_at` 에 남긴다(수집 동의 시각).
- **개인정보처리방침에 수집 항목으로 '휴대전화 번호'와 이용 목적을 추가해야 한다.**
  지금 방침에는 빠져 있다.
